# پریمیوم استور — نسخه ۳

فروشگاه فارسی و راست‌به‌چپ اکانت‌های دیجیتال با FastAPI، SQLite و رابط HTML/CSS/JavaScript. پروژه ربات اصلی جدا و محفوظ است؛ این پوشه وب‌سایت مستقل را دارد؛ همگام‌سازی محصولات با ربات از نسخه ۳ حذف شده است.

## وضعیت واقعی نسخه

ورود موبایلی، حساب مشتری، سبد، تخفیف، سفارش، پنل کارکنان، تیکت و گفت‌وگوی آنلاین پیاده شده‌اند. **درگاه بانکی واقعی هنوز متصل نیست؛ پرداخت فقط شبیه‌ساز محلی است و در production غیرفعال می‌شود.** سرویس پیامکی هنوز توسط مالک انتخاب نشده است؛ آداپتور کاوه‌نگار آماده است، اما ارسال واقعی نیازمند حساب، اعتبار و الگوی تأییدشده است. محصولات و قیمت‌های اولیه نمونه‌اند. فعال‌سازی واقعی اکانت خودکار نیست.

## امکانات

- ورود بدون رمز با کد ۶ رقمی؛ کد ۳ دقیقه اعتبار، حداکثر ۵ تلاش و محدودیت ارسال دارد.
- نشست مشتری ۴۸ ساعت از زمان ورود، بدون تمدید نامحدود؛ خروج از همه دستگاه‌ها؛ نشست کارکنان ۸ ساعت.
- نام و شناسه اختیاری تلگرام یک بار ذخیره می‌شود؛ خرید بعدی از پروفایل استفاده می‌کند.
- دکمه خرید در صفحه اصلی وارد صفحه محصول می‌شود؛ متن، تصاویر و ویدیوی محصول و افزودن به سبد در آن صفحه است.
- قیمت نهایی سمت سرور، کوپن درصدی/مبلغی، محدودیت مصرف و رزرو تراکنشی کد هنگام سفارش.
- پروفایل، تاریخچه سفارش‌ها، تیکت‌های جداگانه و گفت‌وگوی آنلاین با بررسی پیام‌ها هر چند ثانیه.
- مدیریت محصولات، رسانه، سفارش، کاربران، تخفیف، تنظیمات دسته‌بندی‌شده، گزارش فعالیت، کیف پول و مدیریت فعال‌سازی.
- مالک می‌تواند کارمند با نام کاربری/رمز و مجوزهای جزئی بسازد، ویرایش، غیرفعال یا حذف کند. تغییر دسترسی نشست‌های قبلی را باطل می‌کند.
- کانال: https://t.me/premiumstore؛ لینک اینستاگرام از تنظیمات قابل افزودن است و تا آن زمان نمایش داده نمی‌شود.

## اجرای محلی ویندوز

Python 3.11 یا جدیدتر نصب کنید. داخل همین پوشه:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt
.\.venv\Scripts\python -m backend.manage create-owner --username owner
.\.venv\Scripts\python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

رمز مالک را در ترمینال دو بار وارد کنید؛ حداقل ۱۲ کاراکتر. رمز پیش‌فرض وجود ندارد. سایت: http://127.0.0.1:8000/، پنل: http://127.0.0.1:8000/admin/ و مستندات API در محیط محلی: http://127.0.0.1:8000/api/docs.

در حالت پیش‌فرض، کد ورود فقط در اتصال محلی به‌صورت آزمایشی نمایش داده می‌شود و پیامکی ارسال نمی‌شود. برای تست از شماره ساختگی استفاده کنید. دکمه پرداخت نیز برداشت وجه ندارد. دیتابیس و رسانه‌ها محلی هستند و وارد Git نمی‌شوند.

فایل `.env.example` نمونه است و **خودکار بارگذاری نمی‌شود**. در PowerShell متغیرها را قبل از اجرای برنامه تنظیم کنید، برای مثال:

```powershell
$env:PUBLIC_URL = 'http://127.0.0.1:8000'
$env:SMS_MODE = 'demo'
$env:PAYMENT_MODE = 'demo'
```

برای بازیابی رمز مالک (روی سرور و با همان متغیرهای محیطی و دیتابیس):

```powershell
.\.venv\Scripts\python -m backend.manage reset-owner --username owner
```

## راهنمای پنل

۱. وارد `/admin/` شوید. در محصولات، محصول جدید بسازید؛ عنوان، دسته، قیمت **تومان**، توضیح کوتاه، متن کامل، ویژگی‌ها و وضعیت را تکمیل کنید. تصاویر JPEG/PNG/WebP به WebP تبدیل می‌شوند؛ ویدیو MP4 و سقف بارگذاری ۲۵ مگابایت است. لینک HTTPS رسانه نیز قابل استفاده است. HTML دلخواه اجرا نمی‌شود.

۲. پیش‌نویس را بررسی و سپس منتشر کنید. بایگانی محصول برگشت‌پذیر است و محصول را از خرید جدید خارج می‌کند. سفارش‌های قبلی snapshot خود را حفظ می‌کنند.

۳. در تخفیف‌ها، نوع، مقدار، حداقل خرید، تاریخ اعتبار و سقف مصرف را تعیین کنید. مصرف نهایی به تأیید پرداخت وابسته است؛ رزرو لغوشده یا منقضی آزاد می‌شود.

۴. در کارکنان، حساب بسازید و مجوزهای موردنیاز را تیک بزنید. برای مثال پشتیبان: مشاهده/پاسخ/مدیریت تیکت، مشاهده سفارش و مشاهده کاربران. مجوز مشاهده و تغییر مستقل است؛ برای استفاده از صفحه، مجوز مشاهده مرتبط را هم بدهید. فقط مالک کارکنان را مدیریت می‌کند. مجوزها در API هم بررسی می‌شوند.

۵. چت و تیکت صندوق‌های جدا دارند؛ پاسخ، بستن و ارجاع به کارمند از همان صفحه انجام می‌شود. آنلاین‌بودن پشتیبان از فعالیت اخیر حساب دارای مجوز پاسخ چت تشخیص داده می‌شود. این نسخه polling دارد و اعلان بیرون از سایت ارسال نمی‌کند.

۶. تنظیمات کانال، اینستاگرام و پیام فروشگاه را ویرایش کنید. گزارش فعالیت‌ها برای پیگیری تغییرات مدیریتی است. سفارش آزمایشی اجازه تحویل واقعی ندارد.

## راه‌اندازی Ubuntu با دامنه و HTTPS

دستورات زیر برای Ubuntu 24.04 و یک سرویس تک‌پردازه هستند. دامنه نمونه `shop.example.com` را با دامنه خود عوض کنید و رکورد A/AAAA را به سرور متصل کنید. پوشه وب‌سایت را در `/var/www/premiumstore` قرار دهید؛ اگر ریپو را clone کرده‌اید، محتوای پوشه `premium-store` را منتقل کنید، نه کل پوشه ربات.

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip nginx certbot python3-certbot-nginx sqlite3
sudo useradd --system --home /var/lib/premiumstore --shell /usr/sbin/nologin premiumstore
sudo install -d -o premiumstore -g premiumstore -m 700 /var/lib/premiumstore
sudo install -d -m 755 /var/www/premiumstore
# فایل‌های این پروژه را اکنون در /var/www/premiumstore قرار دهید.
cd /var/www/premiumstore
sudo python3 -m venv .venv
sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example /etc/premiumstore.env
sudo chmod 600 /etc/premiumstore.env
sudo nano /etc/premiumstore.env
```

مقادیر production:

```dotenv
APP_ENV=production
PUBLIC_URL=https://shop.example.com
DATABASE_URL=sqlite+aiosqlite:////var/lib/premiumstore/store.db
DATA_DIR=/var/lib/premiumstore
MEDIA_DIR=/var/lib/premiumstore/media
PAYMENT_MODE=disabled
SMS_MODE=disabled
APP_SECRET=REPLACE_WITH_A_RANDOM_SECRET
VAULT_KEY=REPLACE_WITH_FERNET_KEY
TELEGRAM_BOT_TOKEN=
```

برای تولید APP_SECRET، `python3 -c 'import secrets; print(secrets.token_hex(32))'` را روی سرور اجرا و خروجی را فقط در فایل تنظیمات خصوصی ذخیره کنید. این کلید را در چت، ریپو یا اسکرین‌شات قرار ندهید. مقدار ثابت نگه دارید؛ تغییر آن نشست‌ها را باطل می‌کند. `SMS_MODE=disabled` یعنی تا انتخاب سرویس، ورود مشتری فعال نیست. برای کاوه‌نگار، `SMS_MODE=kavenegar` و `KAVENEGAR_API_KEY` و `KAVENEGAR_TEMPLATE` را تنظیم کنید. اتصال سرویس دیگر نیازمند آداپتور جدید در `backend/auth.py` است.

پیش از اجرای سرویس، VAULT_KEY را طبق بخش رمزگذاری تولید و در فایل محیطی تنظیم کنید.

برای ساخت مالک با همان تنظیمات سرور:

```bash
sudo bash -c 'set -a; source /etc/premiumstore.env; set +a; cd /var/www/premiumstore; runuser -u premiumstore -m -- .venv/bin/python -m backend.manage create-owner --username owner'
sudo cp deploy/premiumstore.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now premiumstore
sudo cp deploy/nginx.conf /etc/nginx/sites-available/premiumstore
sudo nano /etc/nginx/sites-available/premiumstore
# server_name _ را به دامنه خود تغییر دهید.
sudo ln -s /etc/nginx/sites-available/premiumstore /etc/nginx/sites-enabled/premiumstore
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d shop.example.com
sudo certbot renew --dry-run
```

اگر سایت پیش‌فرض Nginx با دامنه تداخل دارد، لینک آن را از `sites-enabled` خارج کنید. روی فایروال فقط SSH موردنیاز و ۸۰/۴۴۳ را باز کنید؛ پورت ۸۰۰۰ باید فقط localhost باشد. فایل systemd از یک worker استفاده می‌کند. Nginx فایل‌های public را سرو می‌کند و API و رسانه را به برنامه می‌فرستد. کوکی‌های production فقط روی HTTPS کار می‌کنند؛ با HTTP ورود را امتحان نکنید.

بررسی سرویس:

```bash
sudo systemctl status premiumstore --no-pager
sudo journalctl -u premiumstore -n 60 --no-pager
sudo nginx -t
```

قبل از فروش واقعی باید آداپتور درگاه معتبر، تأیید مبلغ/شناسه تراکنش از سرور درگاه، فرایند تحویل و آزمون‌های آن اضافه شود. تغییر صرف نام PAYMENT_MODE درگاه واقعی ایجاد نمی‌کند؛ مقادیر ناشناخته رد می‌شوند.

## امکانات نسخه ۳ و راهنمای استفاده

### تنظیمات فروشگاه

تنظیمات در چهار گروه قرار دارند: هویت/لینک‌ها/اطلاعیه، پشتیبانی و پیام‌ها، کیف پول، فعال‌سازی و امنیت. تغییر کلیدهای ارتباطی و رمزگذاری صرفاً روی سرور است؛ وضعیت پیکربندی در پنل دیده می‌شود ولی مقدار محرمانه به مرورگر فرستاده نمی‌شود. کلید خام را در فیلدهای یادداشت یا اطلاعیه قرار ندهید.

- چت آنلاین را روشن/خاموش کنید؛ حالت خاموش متن قابل‌ویرایش و لینک ورود/ثبت تیکت نمایش می‌دهد. API هم ارسال پیام چت را رد می‌کند؛ تیکت مستقل باقی می‌ماند.
- برای پیامک پاسخ تیکت، هر دو گزینه «پس از پاسخ پشتیبان...» و «ارسال پیامک اطلاع‌رسانی...» را فعال کنید. متن پیامک عمومی و قابل‌ویرایش است؛ متن خصوصی پاسخ یا رمز اکانت خودکار در SMS کپی نمی‌شود.
- شماره فرستنده پیامک، سقف و کف شارژ، امکان شارژ/مصرف کیف پول، فاصله یادآوری برداشت و راهنمای دریافت اطلاعات اکانت از همین صفحه تنظیم می‌شوند.

### کیف پول

در پنل مشتری، «کیف پول من» مانده و تاریخچه را نشان می‌دهد. مشتری مبلغ دلخواه در بازه مجاز وارد می‌کند و پس از تأیید پرداخت به کیف پول اضافه می‌شود. **این نسخه درگاه بانکی ندارد؛ شارژ در محیط محلی صرفاً شبیه‌ساز و در production غیرفعال است.** کیف پول آزمایشی و واقعی دو دفتر مجزا هستند و اعتبار تست در production قابل مصرف نیست.

در checkout گزینه استفاده از کیف پول، حداکثر تا مبلغ نهایی پس از تخفیف را کسر می‌کند. با پوشش کامل، سفارش همان لحظه پرداخت می‌شود؛ با پوشش جزئی، فقط مانده به درگاه می‌رود. بدون درگاه واقعی در production، فقط پرداخت کامل از اعتبار واقعی ممکن است. رزرو مبلغ در سفارش ناموفق، لغوشده یا منقضی (۲۰ دقیقه) فقط یک بار برمی‌گردد.

پنل > کاربران > جزئیات > کیف پول: برای جایزه مبلغ مثبت و برای اصلاح/کسر مبلغ منفی همراه دلیل وارد کنید. موجودی منفی مجاز نیست. از جزئیات سفارش پرداخت‌شده، «بازپرداخت کامل به کیف پول» مبلغ نهایی را فقط یک بار برمی‌گرداند و سفارش را بازپرداخت‌شده می‌کند. بازپرداخت به کارت بانکی، برداشت کیف پول و بازپرداخت جزئی در این نسخه ارائه نمی‌شوند. دفتر تراکنش append-only است؛ اصلاح اشتباه با تراکنش جبرانی انجام می‌شود، نه حذف سابقه.

### پرونده مشتری و ارسال پیام

دکمه جزئیات در ردیف کاربران و نام مشتری در سفارش به پرونده مشتری می‌رود. سربرگ‌ها: پروفایل/وضعیت و آمار، ارسال پیام/تاریخچه، کیف پول/تراکنش‌ها، سفارش‌ها/جزئیات. مسدودسازی به حساب شماره موبایل متصل است و نشست‌های فعال را باطل می‌کند.

برای پیام دستی، SMS و/یا تلگرام را تیک بزنید. شماره پیامک از موبایل تأییدشده حساب می‌آید. تلگرام به شناسه **عددی مثبت chat_id** نیاز دارد؛ یوزرنیم به‌تنهایی کافی نیست. مشتری باید ربات شما را Start کرده باشد. شناسه را از گفت‌وگوی تأییدشده مشتری بگیرید و تطابق را قبل از ثبت مقصد بررسی کنید. این اتصال فقط پیام خروجی است و دیتابیس، محصولات، کیف پول یا سفارش‌های ربات را نمی‌خواند/همگام نمی‌کند.

کلید کاوه‌نگار و توکن ربات در `KAVENEGAR_API_KEY` و `TELEGRAM_BOT_TOKEN` روی سرور تنظیم می‌شوند؛ ارسال SMS اطلاع‌رسانی از روش عمومی `sms/send` استفاده می‌کند و خط باید مجوز ارسال داشته باشد. الگوی OTP همچنان مستقل است. سرویس دیگر به آداپتور جدید نیاز دارد. در development/test، ارسال خروجی حتی با کلید موجود صرفاً `simulated` ثبت می‌شود. برای ارسال واقعی production و سرویس معتبر لازم است.

صف ماندگار پیام‌ها هر چند ثانیه پردازش می‌شود. تاریخچه وضعیت‌های در صف، ارسال‌شده، غیرفعال، ناموفق، آزمایشی یا نامشخص را نشان می‌دهد. در قطع ارتباط بعد از ارسال، retry خودکار انجام نمی‌شود تا پیام تکراری نرود؛ در وضعیت نامشخص ابتدا گزارش ارائه‌دهنده را بررسی کنید، سپس در صورت نیاز پیام جدید بفرستید. worker فعلی برای یک پردازه طراحی شده؛ systemd را با یک worker نگه دارید.

### دریافت اطلاعات اکانت برای محصول

در فرم محصول گزینه «برای هر واحد محصول، نام کاربری و رمز اکانت...» را روشن کنید. صفحه محصول نیاز به این اطلاعات را توضیح می‌دهد. در تکمیل سفارش به تعداد واحدهای آن محصول، فیلد نام کاربری/ایمیل و رمز نمایش داده می‌شود. سرور تعداد و الزامی‌بودن اطلاعات را بررسی می‌کند؛ رمز در localStorage، سفارش عمومی، گزارش فعالیت یا صف پیامک قرار نمی‌گیرد.

کارمند دارای مجوز `orders.secrets` از جزئیات سفارش، اطلاعات را با درخواست جدا آشکار می‌کند. مشاهده audit می‌شود و پس از یک دقیقه از صفحه پنهان می‌شود. فقط اطلاعات اکانتی که مشتری اجازه فعال‌سازی آن را داده ثبت شود؛ کد یک‌بارمصرف و رمز بانکی دریافت نمی‌شود.

### مدیریت فعال‌سازی

ابتدا در «کارت‌های من» کارت یک‌بارمصرف یا قابل شارژ با نام قابل تشخیص و شماره ثبت کنید. شماره کامل رمزگذاری و در فهرست فقط چهار رقم آخر نمایش داده می‌شود؛ **CVV/CVC و PIN ذخیره نشود**. شماره کامل فقط با مجوز `activations.secrets` و با ثبت مشاهده در audit آشکار می‌شود.

سپس فعال‌سازی را با جست‌وجوی کارت و مشتری ایجاد کنید: سرویس، ایمیل، مشخصات اکانت، رمز اکانت، تاریخ پرداخت، تاریخ برداشت بعدی، وضعیت برداشت خودکار و شماره سفارش اختیاری. سفارش باید متعلق به همان مشتری باشد. کارت یک‌بارمصرف برای رکورد دوم پذیرفته نمی‌شود؛ کارت قابل شارژ چند فعال‌سازی دارد. برای تغییر اطلاعات، نسخه رکورد کنترل می‌شود تا ویرایش همکار بازنویسی نشود. رمز خالی هنگام ویرایش یعنی حفظ رمز قبلی.

جست‌وجو بر اساس شماره کامل کارت یا چهار رقم آخر، نام کارت، ایمیل، موبایل، شناسه سفارش، نام اکانت یا سرویس است. جست‌وجوی شماره کامل با HMAC انجام می‌شود و رمزگشایی همه کارت‌ها لازم نیست. موارد نزدیک و عقب‌افتاده در داشبورد و صفحه فعال‌سازی نمایش داده می‌شوند. پس از پرداخت جدید، تاریخ برداشت بعدی را دستی اصلاح کنید؛ این بخش برداشت بانکی انجام نمی‌دهد یا برداشت سرویس خارجی را لغو نمی‌کند. یادآوری داخل پنل است، نه پیامک خودکار.

### مجوزهای جدید کارکنان

`wallet.read` مشاهده، `wallet.adjust` اصلاح/جایزه، `wallet.refund` بازپرداخت؛ `messages.read` تاریخچه، `messages.send` ارسال/مقصد تلگرام؛ `activations.read` مشاهده، `activations.write` ثبت/ویرایش، `activations.secrets` آشکارسازی کارت/رمز؛ `orders.secrets` مشاهده اطلاعات ورودی سفارش. برای کار با پرونده مشتری، `customers.read` و برای انتخاب مشتری فعال‌سازی نیز همین مجوز لازم است. برای عملیات کیف پول، مجوز مشاهده کیف پول را هم بدهید. دسترسی جدید خودکار به کارکنان قدیمی داده نمی‌شود؛ مالک آن را انتخاب می‌کند.

### رمزگذاری و ارتقا از نسخه ۲

پیش از ارتقا از دیتابیس بکاپ بگیرید؛ requirements جدید را نصب کنید. migration فقط ستون نیاز به اطلاعات اکانت و جداول نسخه۳ را اضافه می‌کند؛ سفارش‌ها، کاربران، رمز مالک و نشست‌ها حفظ می‌شوند. کد، endpoint، منو و worker همگام‌سازی ربات حذف شده‌اند. جداول تاریخی همگام‌سازی ممکن است برای حفظ داده در SQLite باقی بمانند ولی دیگر مصرف نمی‌شوند. متغیر `BOT_DATABASE_PATH` را حذف کنید؛ سایت دیگر دیتابیس ربات را باز نمی‌کند.

یک بار کلید رمزگذاری تولید کنید:

```bash
/var/www/premiumstore/.venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

خروجی را فقط در `VAULT_KEY` فایل خصوصی `/etc/premiumstore.env` قرار دهید و سرویس را restart کنید. در محیط محلی کلید مستقل در `.local/vault-key` ساخته می‌شود. کلید و دیتابیس باید با هم بکاپ شوند؛ حذف یا تعویض بی‌برنامه کلید، شماره کارت و رمزهای قبلی را غیرقابل بازیابی می‌کند. تغییر APP_SECRET نیز HMAC جست‌وجوی کارت‌های قبلی را نامعتبر می‌کند. کلید را در Git یا پیام‌رسان قرار ندهید. این قابلیت ذخیره اطلاعات عملیاتی است و گواهی انطباق PCI محسوب نمی‌شود؛ کنترل دسترسی سرور و بکاپ‌ها نیز ضروری است.

## نگهداری، بکاپ و به‌روزرسانی

از دیتابیس سایت، پوشه media و کلیدهای APP_SECRET و VAULT_KEY بکاپ هماهنگ بگیرید. بکاپ ربات مستقل است. بکاپ خصوصی و خارج web root نگه دارید. برای SQLite زنده از فرمان `.backup` استفاده کنید، نه کپی تنها فایل db هنگام نوشتن:

```bash
sudo install -d -m 700 /var/backups/premiumstore
sudo sqlite3 /var/lib/premiumstore/store.db '.backup /var/backups/premiumstore/store.db'
sudo cp -a /var/lib/premiumstore/media /var/backups/premiumstore/
```

برای بکاپ کاملاً هماهنگ سایت، نویسنده سایت را موقتاً متوقف کنید. کلید محیطی را جدا و رمزگذاری‌شده نگه دارید. بازیابی را روی محیط آزمایشی بررسی کنید. در به‌روزرسانی ابتدا بکاپ، سپس جایگزینی کد/نصب requirements و restart؛ پوشه داده را جایگزین نکنید. مهاجرت نسخه۳ افزایشی است و جداول قدیمی سفارش را پاک نمی‌کند. نسخه‌های آتی نیازمند migration بررسی‌شده‌اند.

## امنیت و آزمون

نشست سمت سرور با توکن هش‌شده، HttpOnly/SameSite و Secure در production؛ CSRF برای عملیات احرازشده؛ کنترل مبدأ؛ هش scrypt برای رمز کارکنان؛ کنترل دسترسی روی هر API؛ محدودیت اندازه فایل/درخواست؛ ثبت رویداد؛ escape خروجی؛ جلوگیری از پرداخت تکراری و مصرف همزمان کوپن.

```powershell
.\.venv\Scripts\python -m pytest -q
Get-ChildItem public -Filter *.js -Recurse | ForEach-Object { node --check $_.FullName }
```

آزمون‌ها از دیتابیس موقت و اطلاعات ساختگی استفاده می‌کنند. گزارش محدوده بررسی: `docs/verification.md`. این تست‌ها جای آزمون عملی روی سرور، سرویس پیامکی، درگاه و نسخه واقعی ربات را نمی‌گیرند.

## ساختار

`backend/`: API، کیف پول، پیام‌رسانی، رمزگذاری و مدیریت فعال‌سازی؛ `public/`: سایت و پنل؛ `tests/`: تست؛ `deploy/`: Nginx و systemd؛ `catalog.json`: داده اولیه فقط در اولین راه‌اندازی؛ `.env.example`: تنظیمات نمونه. ویرایش catalog.json بعد از ایجاد دیتابیس، محصولات موجود را تغییر نمی‌دهد؛ از پنل استفاده کنید. دیتابیس، کلیدها، محیط مجازی، رسانه مشتری و فایل env را commit نکنید.
